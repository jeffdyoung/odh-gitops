{{- if .Values.ingest.writer.create }}

Spokes authenticate as {{ include "ai-grid-o11y-hub.writerName" . }}. The chart creates the
identity but cannot mint its token, which is not a declarative object, and no object this
chart renders ever contains it. Mint it here:

  oc create token {{ include "ai-grid-o11y-hub.writerName" . }} -n {{ .Values.namespace }} --duration=8760h > hub-writer-token

It then reaches spokes one of two ways, and you need only one of them.
{{ if .Values.spokePolicy.enabled }}
ACM: step 1 below puts it in Secret {{ .Values.spokePolicy.credentialSecretName }}, and the
policy delivers it to every selected spoke. Nothing else to do per spoke.
{{- else }}
ACM: set spokePolicy.enabled and hold it in a Secret this hub's policy reads, which then
delivers it to every selected spoke.
{{- end }}
Directly: hand the file to the ai-grid-o11y-spoke chart on the spoke cluster, which creates
the Secret its collector mounts:

  helm upgrade --install rhoai ./charts/rhai-on-openshift-chart \
    -f docs/examples/values-ai-grid-o11y-spoke.yaml \
    --set-file ai-grid-o11y-spoke.credential.token=./hub-writer-token \
    -n rhoai-gitops

Either way, delete the local file afterwards. Nothing rotates the token and no object reports
its age; treat the expiry as an operational commitment, not a default.
{{- end }}

usageLogs.storage is not delivered by this policy. A spoke whose usage logs are not already
running locally needs it set by whatever installs RHOAI there.

Compliance says the Secret matches the policy, not that the token works. An expired or
wrongly scoped token distributes as Compliant, and ManagedClusterView refuses Secrets, so
the hub cannot read back what a spoke holds. The signal that the chain works is records
arriving here with the right cluster_name.
